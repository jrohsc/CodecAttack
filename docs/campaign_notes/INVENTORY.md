## Metric set per scenario

Common: `target_substring_match`, `wer`, `snr_db`. Finance/interview also include `exact_match` (auth/verdict are sensitive to single-character errors).

`tool_name_match` exists in the metric registry but is **best-effort substring** — Qwen2-Audio / AF3 / Qwen2.5-Omni are not function-calling-tuned. See `src/audio_agent_bench/metrics/tool_call.py`.

## Known gotchas

- **Flexible audio duration**: each carrier wav keeps its source length. Do not pad to a fixed window. See `memory:feedback_flexible_duration.md`.
- **HR prompt dominance** (case 02): the HR system prompt alone makes Qwen2-Audio favor positive verdicts on Mandarin audio, regardless of attack. Substring-of-target match required, not flip rate.
- **Real vs simulated OTA** (case 04): this benchmark is simulated only. Real-hardware results stay in `3_results_physical_attack/`; do not conflate.
- **Per-attack-type targets differ** (case 03 latent vs waveform): latent QA attacks target SayCan action plans; waveform attacks target spoken commands. The `_target_map.json` per scenario handles this — each wav is scored against its own target.
- **GPU**: Qwen2-Audio-7B at bfloat16 needs ~14 GB. If GPU is occupied by other jobs, submit via Slurm to a free node.

## Provenance traceability

Every audio file in `scenarios/NN_*/audio/` is a symlink whose target path encodes its origin. To trace any file:

```bash
ls -L scenarios/03_music_industry_bypass/audio/latent/qa__calm_1__saycan_000.wav
# → resolves to /work/.../codec_attack/1_results_qa/benchmark_qwen2_audio_eps1.0_calm_1_saycan/audio/calm_1__saycan_000.wav
```
